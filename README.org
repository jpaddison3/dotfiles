** Chrome in BB Codex

Run ~make install-bb-chrome~ from the permanent dotfiles clone on a Mac that
is already set up. The skill link depends on the checkout staying in place,
so the installer rejects linked worktrees and known scratch checkouts.
~newcomputer.bash~ runs the same installer on new machines.
The installer links one skill at ~~/.bb/skills/bb-chrome~. If you move the
checkout, rerun the installer from its new location to update the link.
Start a fresh BB Codex thread and ask it to check something in an existing
Chrome tab.

Use the ChatGPT extension in the Chrome profile with the tab you want to
check. The skill can delegate to the Chrome integration bundled with
~/Applications/ChatGPT.app~ if the current session lacks a working Chrome
integration. See the [[https://learn.chatgpt.com/docs/chrome-extension][ChatGPT browser extension guide]] for setup.

To uninstall the skill, trash the symlink at ~~/.bb/skills/bb-chrome~.
Running ~newcomputer.bash~ again reinstalls it.

** Inbox triage Raycast commands

Install or update the three focused Raycast Script Commands from this checkout:

#+begin_src sh
make install-inbox-triage-raycast
#+end_src

This copies only the scripts into
~/.local/share/raycast/scripts/inbox-triage/~ and leaves other Raycast scripts
and settings alone. Re-run the command after updating this checkout. To
uninstall, remove only those three installed scripts from that directory.

In Raycast, open **Settings → Extensions**, choose **+ → Add Script Directory**,
and add ~/.local/share/raycast/scripts/inbox-triage/~. Select **Inbox Triage**
and enter **Ctrl+Option+Command+I** in its **Hotkey** field. Leave **Inbox
Triage — BOD** and **Inbox Triage — EOD** without default hotkeys. If Raycast
reports a conflicting assignment, resolve it in Raycast rather than changing
another command here.

The scripts call the separately installed ~inbox-triage-launch~ backend once
per invocation. Install that backend first in the 80k-coding-tools checkout
with ~make install-inbox-triage~. The auto command delegates local-time mode
selection to the backend; the BOD and EOD commands pass their explicit modes.

** SSH only over Tailscale

Run ~make install-pf-ssh~ to let SSH in only from this Mac and from Tailscale
(~100.64.0.0/10~ and ~fd7a:115c:a1e0::/48~); connections to port 22 from any
other network are dropped. It uses pf rather than the Application Firewall in
System Settings, which filters by app, not by source address, and always lets
the built-in ~sshd~ through. The rules live in ~pf-ssh.rules~, loaded into the
pf anchor ~com.apple/150.jpaddison-ssh~ at boot by a root LaunchDaemon, so
~/etc/pf.conf~ stays stock. Nothing besides port 22 is affected.

Check: ~sudo pfctl -a com.apple/150.jpaddison-ssh -sr~. Turn off until the next
boot: ~sudo pfctl -a com.apple/150.jpaddison-ssh -F rules~. Remove for good with
the undo steps at the top of ~install-pf-ssh.sh~.
